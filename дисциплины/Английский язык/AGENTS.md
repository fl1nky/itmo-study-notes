# Правила добавления IT English

Применяй эти правила ко всему английскому разделу вместе с корневым `AGENTS.md`. Здесь находятся все шаблоны для добавления слов, фразовых глаголов, реплик и тематических сцен. Не создавай отдельную папку шаблонов или ссылки на них в читательской навигации.

## Общий подход

- Строй материал вокруг рабочей IT-ситуации: выбранный смысл → готовая связка → пример → собственная реплика → воспроизведение без подсказки.
- Выбирай полезные тематические выражения, которые позволяют обсуждать задачу, ошибку, решение или результат. Объясняй один смысл за раз.
- В учебных страницах, индексах, тренажёре и публичных JSON не публикуй разделы источников, библиографию и ссылки на справочники. Проверяй неоднозначные значения и грамматику; сведения о проверке сохраняй только в игнорируемом `.local-context/` корня репозитория.
- Примеры и диалоги составляй самостоятельно. Не выдавай их за цитаты преподавателя или словаря. Сохраняй смысл и естественный порядок слов.
- Не придумывай дату занятия, требования преподавателя и факт освоения. Тематический словарь не оформляй как датированную лекцию; дату добавления отдельной записи указывай только по фактическому добавлению.
- Пиши пояснения по-русски, речевые примеры по-английски. Раскрывай ответ отдельно под каждым вопросом; между вопросами ставь `---` с пустыми строками вокруг.
- В `README.md` раздела оставляй выбор тем и материалы для учёбы. Заполненный пример и способы повторения находятся в `Как вести словарь.md`; инструкции добавления и пустые шаблоны — только здесь.

### Дополнение для фразового глагола

Вставляй после «Собрал в связку». Проверяй свойства именно выбранного значения. Если прямого объекта нет, не придумывай вариант с `it`; прямо укажи, что он неприменим. Пример: `sign in to an account`, а не искусственное `sign it in` для входа в учётную запись.

~~~~markdown
### Как устроен глагол

- **Основа — прошедшее — причастие:** …
- **Полная схема с объектом или предлогом:** …
- **Порядок слов:** разделяемый / неразделяемый / без прямого объекта в этом значении.
- **Вариант с it / them / me:** … / неприменим, потому что …
- **Тон и ситуация употребления:** …
~~~~

## Шаблон тематической сцены

~~~~markdown
# [IT-тема]
~~~~

## Добавление и проверка

1. Сначала прочитай эти правила и локальный `.local-context/WORKFLOW.md` корня репозитория. Следуй шаблону; не возвращай отдельные файлы шаблонов и страницу источников.
2. В основном рабочем каталоге генератор — `tools/build-english-scenarios.py`, данные — `tools/english_scenarios_data.py`. Их точное размещение относительно каталога указано в локальном workflow. Изменяй данные и генератор перед пересборкой, чтобы ручная правка не исчезла.
3. Для новой сцены задай устойчивый `id`, название, ситуацию, цель, 6 строк слов (`en | ru | chunk | example | translation`), 3 строки глаголов (`en | ru | pattern | forms | note | example | translation`), 2 пары реплик (`en | ru`), диалог и перевод, тонкость, упражнение на порядок слов, речевое задание и опорный ответ. Внутри значения не используй разделитель `|`.
4. В генераторе добавь предложения с пропусками и ответы для новых глаголов. Обнови фактические количества тем и записей в индексах; не копируй старые числа, если подборка изменилась.
5. Сохраняй ID всех прежних записей и ключ прогресса `itmo-it-english-v1`. Публичные JSON содержат только учебные данные, без поля `source` и ссылок на источники.
6. Пересобери Markdown, индексы, JSON и автономный `Повторение.html`. Проверь локальные ссылки, соответствие данных тренажёру, раскрытия и разделители вопросов. Отдельно проверь управление новых глаголов и естественность примеров.
7. Не отмечай за пользователя освоение, выполнение или повторение. Выполненную проверку и результат публикации фиксируй в локальном workflow.
